# customer-summary

Invoke from Liquid

## Set up

1. Set up a workspace.
2. Open Server logic.
3. Select + New server logic.
4. Name it exactly `customer-summary`. That name is the API resource name.
5. Select + Add roles and add a web role the visiting user holds.
6. Select Edit code, then Open Visual Studio Code.
7. Replace the file content with `customer-summary.js` and save.
8. Configure the site settings, allowed domains and table permissions as listed in permission-checklist.md.
9. Paste `customer-summary.client.liquid` into a page or web template.

## Endpoint

`{% serverlogic name: 'customer-summary', operation: 'getSummary', output: result %}`

The client file shows the version with `input:`.

## Request path

Page render Liquid page → Tag serverlogic → Handler function getSummary() → Returns result object

## Troubleshooting

- The `x-ms-user-trace` response header holds base64 JSON, a list of `{ Level, MessageCode, Message }`, including `Server.Logger` output.
- An `RTSL01` validation error means the whole file doesn't run and the caller gets HTTP 400.
- HTTP 403 when the tenant's "Disable external service calls from Server Logic" governance control is on: https://learn.microsoft.com/en-us/power-pages/security/disable-external-service-calls

## Secrets

Hold secrets in Azure Key Vault, surface them through an environment variable, and reference them through a site setting. The generated code never holds a literal secret.

## Notes

- Liquid invocation needs no token and reads Server.Context.Input rather than Body or QueryParameters. Long operations cause delayed rendering.
